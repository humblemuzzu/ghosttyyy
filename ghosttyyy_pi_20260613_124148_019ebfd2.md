## Why your friend gets "prompt is too long" → exit 1

The `contextWindow` number in models.json is **only pi's internal bookkeeping** — it controls when pi compacts. It does **not** grant 1M context from Anthropic. Real 1M context on Claude is a beta capability gated by account tier (the `context-1m-2025-08-07` beta; the SDK that ships with pi references it, but the actual entitlement lives on the Anthropic/Claude subscription side).

So when your friend has the same `contextWindow: 1000000` override but their account does **not** have 1M access:

1. pi thinks the window is 1M, so `shouldCompact` stays false all the way up to ~984k — it never compacts at 200k.
2. The conversation grows past the real 200k API ceiling.
3. Anthropic rejects the request: `"prompt is too long: 213462 tokens > 200000 maximum"`.
4. pi *does* have overflow recovery (`isContextOverflow` matches `/prompt is too long/i`, then it tries one compact-and-retry). But this only works if it's running interactively and the retry succeeds. If recovery fails once (`_overflowRecoveryAttempted` guard in `agent-session.js`), or it's a print/non-interactive run, the error surfaces as fatal → **exit code 1**.

For you it works because your Anthropic plan actually serves 1M context, so the request never crosses a real ceiling before compaction would kick in.

The mismatch to avoid: telling pi the window is 1M while the provider only honors 200k. That guarantees the overflow.

## 1. The compaction on/off switch — GLOBAL

This is a **single global flag**. It applies to every model — opus, deepseek, kimi, local, all of them. There is no per-model compaction toggle in pi. You can't turn compaction on for opus but off for kimi via settings; it's one switch for everything.

## 2. *When* it triggers — PER-MODEL (derived, not a setting)

pi never has a fixed "compact at X tokens" number. The trigger is computed live, per model, in `compaction.js`:
```js
shouldCompact = contextTokens > (contextWindow − reserveTokens)
```
- `reserveTokens` defaults to **16,384** (global, you haven't overridden it).
- `contextWindow` comes from **each model's own definition**.

So the *effective* compaction point is different for every model, because each has its own window:

| Model | contextWindow | compacts at (~98%) |
|---|---|---|
| `claude-opus-4-6` / `4-7` | **1,000,000** (your override) | ~983k |
| `deepseek-v4-pro` / `flash` | 1,048,576 | ~1.03M |
| `kimi-for-coding` | 262,144 | ~246k |
| `crof/glm-5.1` etc | 131,072 | ~115k |
